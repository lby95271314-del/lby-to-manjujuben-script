# 项目参数与完整交稿包

先使用用户已经给出的信息，不重复询问。没有指定媒介时可沿用竖屏漫剧假设并说明；媒介会影响表演、旁白量和视觉复杂度。用户只要求局部改稿时，不强制重新规划全剧。

## 参数

`assets/project-config.json` 是可修改的范例，不是平台统一规则。校验器允许省略配置并使用默认值；未知字段、错误类型、负数预算和不合法声音标签会报配置错误。

| 字段 | 作用 |
|---|---|
| `target_seconds` | 每集目标秒数下限与上限；估算偏离时提醒 |
| `speech_chars_per_second` | 汉字、英文字母、数字的计数单位/秒；默认 4。英语较多时调整，不等同于词/秒 |
| `pause_seconds_per_dialogue` | 每行对白默认停顿；显式节拍的“停顿”会替代该默认值 |
| `max_scenes` | 每集场次数提醒；不等同于独立地点数 |
| `max_spoken_chars` | 含 OS、VO、旁白的配音预算提醒 |
| `body_chars_range` | 正文量提醒，排除标题、人物标签及编剧注释 |
| `budget_policy` | `warn` 为提醒，`error` 将预算超限视为项目硬要求 |
| `aliases` | 别名到标准角色名映射；正文和人物名单使用同一映射 |
| `voice_tags` | `inner`、`remote`、`offscreen` 的项目标记，默认 OS、VO、画外；三者不可相同 |

完整创作还可在单独的交稿资料中记录目标媒介、受众、题材、总集数、免费集数、付费卡点、人物上限、独立地点预算和固定道具；这些不是当前校验配置字段，不伪装成单集脚本已经自动校验的项目。

声音标签只改变表达约定，不改变戏剧事实：内心独白仍不可被其他人物直接听到。别名不应覆盖另一个独立角色的姓名。

## 完整交稿包

用户要求整包时，另写 `交稿资料.md`，与可校验的剧本正文分开：

1. **剧本信息**：题材、媒介、总集数、单集时长、预计总时长，用户指定的免费集数/卡点；未指定的商业参数标明待定，不编成事实。
2. **一句话故事**：通常约 50 字，写主角、困境、行动与核心看点，长度服从客户模板。
3. **完整故事大纲**：写清从开端到结局的主线、关键转折及因果；参考 500–2000 字，按项目调整，包含结局，不能只有卖点介绍。
4. **主要人物小传**：优先主角、主要对手及推动主线的配角；包括身份、年龄/外表、背景、性格、目标动机、关系、成长弧线，避免为所有路人编长传。
5. **分集梗概**：项目需要时，记录核心事件、变化、钩子及后续兑现位置；免费转付费卡点必须与实际分集对应。

长篇改编或设计反转、情绪时，按 [story-methods.md](story-methods.md) 记录必要的原著事件映射、信息差和集间承接。用户已给出总集数时先评估可容纳的戏剧任务；需要调整集数则给出取舍依据，不自行忽略用户要求。没有指定集数时提出有内容依据的建议，不仅按原文字数换算。

可在交稿资料中简记观众期待（如尊严恢复、能力认可、关系修复、解谜或安全感）、首集核心问题、主要反转和伏笔兑现位置。这些是人工创作说明，不是新增 JSON 配置字段。

## 创作与制作审读

- 每集核心事件明确；事件结束应改变局面或人物选择。
- 强开场应来自冲突或异常；不为凑“黄金三秒”破坏理解与因果。
- 反转数量不固定；增加反转前检查铺垫、信息来源与后果。
- 主角和对手都应有具体目标与行动能力；侮辱、拉踩并非所有题材必需。
- 角色的道具、动作、说话方式形成记忆点，但不能每场重复口号。
- 旁白补必要信息，避免与已能看到的画面重复解释。
- 统计场次与独立地点；同一地点更换时间不必建立新的地点资产。
- 预估时长最终结合配音、表演和成片校正。
