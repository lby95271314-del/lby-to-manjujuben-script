# 改编取舍、补戏与修稿
整篇改编、原文偏叙述、需要加强开头或中后段、长篇续写和局部改稿时按需读取。与 [adaptation-workflow.md](adaptation-workflow.md) 配合；正文仍用既有格式。本方法吸收用户两份资料的可执行优点，不引入逐镜分镜或生成模型参数。

## 1. 先识别材料功能，再选操作
原文可同时承担多种功能，不强制逐句分类或填写全表。只在删留有争议时区分：
| 材料 | 判断与处理 |
|---|---|
| 核心剧情 | 保住目标、规则、关键转折与结果；表达可重组 |
| 人物关系 | 保住改变信任、距离、合作或利益的节点；不强制增加感情线 |
| 可视信息 | 画面已能传达时删掉重复说明，保留理解必需的指认 |
| 心理 | 优先转成有刺激来源的选择、动作或对白；必要心声仍可保留 |
| 说明 | 在当前任务、交易、争执或验证中使用；不强行把所有说明变争吵 |
| 重复 | 判断是否新增含义、代价或情绪；同功能且无增量才合并 |

四种操作按戏剧价值选择，不由原文字数决定：
- 保留：事件已有目标、行动和变化，保留核心，口语与衔接可微调。
- 压缩：多段只表达同一事实；留下理解、情绪与反转所需的最少材料。
- 改写：事实或关系功能有价值，换成能观察的行动、互动或物件。
- 扩写：原文只给结果，关键过程缺失；补成目标—尝试—阻碍—调整—结果—反馈。没有阻碍和选择价值时不硬扩成一场。

扩写前检查：是否展现已成立的能力、获得必要证据、推进重要关系、承担新代价或兑现承诺；预算是否容纳；能否删并低价值材料给它腾时间。新增场景、危险或肢体动作本身不是扩写理由。避免凭空增加救援、身份、资源或规则。

## 2. 原创补戏：补表现与过程，守住关键事实
先读取用户本次改编幅度。一般小说转剧本允许补齐同功能动作、合理交锋、过渡与反应；明确要求严格保留时收窄。改变核心身份、关系、世界规则、关键结果或结局时按改编授权判断，未授权的重构另列方案。

每个重要新增过三项检查：
1. 人物依据：此人当前知道什么、会怎样选择、具备何种权限或能力？新增主动性不能变成突然全能。
2. 后续兼容：对知情、道具、时间、关系和关键结果有什么影响？不得悄悄制造后续无法成立的新事实。
3. 明确功能：修补何处因果，或推进何种任务、关系、期待与反馈？只为热闹的动作删去。

新增开头优先让已有矛盾提前被执行：限时交接、拒签、隐藏物件被核对、选择被迫作出。新增线索须写明取得方式、可信程度、谁能看到及何时使用；反转库提供机制，不提供原作事实。

## 3. 来源追踪与清洁正文
关键结构变化、证据、能力、关系节点或新增反转，在独立的创作资料/改编说明中登记。普通润色无需逐句贴标签。
| 剧本集场/关键动作 | 原文章节/段落与事实 | 来源类别 | 操作与理由 | 新增条件及后续影响 |
|---|---|---|---|---|
| 真实正文位置 | 可回查位置；未见则写待补 | 原文保留/原文改写/原创新增 | 保留/压缩/改写/扩写 | 知情、规则、道具、关系、结果 |

“原文改写”表示有原著事实或功能依据，不表示新增台词是原句。混合场景分别标出核心事件与新增关键过程；不要把整场统一标成保留。原文没有的证据来源或关键道具应标新增，不能藏在“外化”名下。纯正文不塞来源标签，不新增解析器不支持的字段。用户只要正文时内部核对即可。

## 4. 两种发动机与开头承诺
故事发动机：主角为什么不断采取下一项行动，如争取署名、查出真相、完成交易。
追剧发动机：观众期待哪个尚未回答的问题或变化，如谁利用了谁、关系能否修复、弱者如何取得认可。两者可以相同，不强制写爱情或秘密。

首集确定承诺后，按实际情节追踪：
| 开头许诺的体验/问题 | 本集可见进展 | 中段改变条件或策略 | 阶段反馈 | 最终回答/节选待补 |
|---|---|---|---|---|

把进展写进动作与选择，不能只在集尾重复同一问句。开头许诺查明陷害，后续任务就应取得或排除证据、逼出选择并产生后果。关系主线可通过任务中的让步、拒绝、合作和代价推进；不要只重复靠近与脸红。集尾可以断在未决选择或揭示前，但已有阶段反馈不要反复撤回。最终集兑现主问题，不强加下一集悬念。

## 5. 场景密度与动作对白
优先让任务与重要关系在同一行动中推进。一个有效场景可兼有信息、选择、关系与兑现；不要求每场达到固定功能数，不为增加功能加入无关人物。
动作链写清：刺激/目的 → 谁对什么做了什么 → 对方反应 → 下一项选择。对白用于求证、拖延、交换或反制，触发行动；同步动作必须与诉求相关。安静的对话也可以有效，不用走动、摸头发或频繁换场伪造节奏。

对白期间可递、收、挡、打开或核对当前已有道具；重要行动让结果可见。复杂动作需要简化时保持戏剧功能、能力条件、证据可信度和关系阶段，不能因“易生成”偷偷更换证据。不给任何视频模型承诺生成成功。镜头概述强调叙事重点，不写逐镜参数。

剧情节奏看条件与选择变化；视觉节奏看观众如何读出这些变化。换角度、表情或地点不能单独算剧情升级。连续同功能日常过程可概括成几项可见事件；跨时间地点仍使用既有场头、字幕等标记，不直接引入未经格式脚本支持的蒙太奇块。

## 6. 诊断后修复
| 症状 | 先查什么 | 优先修复 |
|---|---|---|
| 开头炸，后面松 | 抓手是否引出主线任务，承诺是否推进 | 让第一行动接上抓手；删除游离爆点 |
| 原文短，成稿也只有结果 | 缺的是必要过程还是无价值过场 | 有必要才扩写尝试、阻碍、调整和反馈 |
| 长段站桩 | 双方是否争取改变对方选择 | 把诉求落实到已有道具/程序；允许无动作的有效交锋 |
| 反转生硬 | 证据、能力、知情是否提前成立 | 补来源与伏笔，必要时改反转机制，不能只加震惊 |
| 中段重复 | 条件/策略/关系有没有改变 | 合并同级冲突，增加原作支持的新代价或选择 |
| 高潮后仓促 | 成功/失败对人物与关系的结果是否可见 | 留真实容量给接受、补救、兑现或收束 |
| 改一处坏多处 | 哪些后续依赖被改事实 | 沿依赖链修伏笔、知情、道具、台词和集尾承接 |

修改明确问题时先定位并局部修复；结构问题影响全局时说明影响范围，不能以“只改局部”为由保留已失效后果。输出简短改动清单，按改后正文重新估时；不强制先等用户确认已明确的修改要求。

## 7. 分批与自包含交付
大体量无法一批完整写完时保留细纲，不把后段压成摘要冒充成稿。批次进度与待写范围另存资料；续写前读取原作对应范围、人物规则、末态和未回收伏笔。只有用户要求逐批审阅才等待每批确认。
恢复卡可用：已写集场｜当前任务/承诺进展｜角色知情与关系｜关键道具状态/持有者｜叙事时间｜未回收伏笔｜下一批起点。
完成后按实际输出更新，不用计划代替已写事实。合并交稿每场保持明确地点、时间与人物，不依赖“同上”“沿用聊天设定”；重复资料放附录，不塞正文。检查时代器物与语言时区分原著设定和待考据项，不声称调用未提供的知识库。

四种操作与来源区分示例见 [adaptation-decisions-example.md](adaptation-decisions-example.md)。
